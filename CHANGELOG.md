# Changelog — What I Tried and Changed

- **Map tiles:** First attempt used CartoDB Positron tiles, which now require an API key and showed a warning instead of rendering reliably. Switched to default OpenStreetMap tiles, which need no key and render for anyone opening the map.
- **DBSCAN parameters:** Initially tried `eps` in degrees directly on raw lat/lon, which doesn't correspond to a consistent real-world distance (a degree of longitude is shorter than a degree of latitude away from the equator). Switched to projecting points to an approximate local meters grid (equirectangular projection centered on Karachi) first, then ran DBSCAN with `eps=600` meters, `min_samples=25` — this gave geographically sensible, interpretable clusters.
- **Underserved threshold:** Tried a 3 km cutoff first, which flagged almost half the clusters as underserved and didn't usefully separate "real gaps" from normal variation. Settled on 5 km, which matches the point where distance clearly diverges from the well-served clusters (DHA, Gulshan-e-Iqbal, Korangi all average 2-2.5 km; the flagged ones jump to 6-13 km).
- **Sea-point detection:** Used a simplified rectangular coastline rule (`lat < 24.76` within a specific longitude band) rather than a real coastline shapefile, since a precise Karachi coastline polygon wasn't available in this environment. Documented this as a limitation rather than presenting it as precise.
- **Validation order:** Originally checked for swapped coordinates before checking for physically impossible values, which caused a few impossible values (e.g., longitude 400) to be mis-evaluated by the swap-fit check. Reordered validation to always remove impossible/missing values first, then check for swaps, then check for sea points.
